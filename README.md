# TaskFlow (v3 - 機能追加版)

追加された最新機能がすべて盛り込まれています。

- サブタスクのホーム画面展開＆個別完了チェック
- タスク完了時の遅延消去（グレーアウト）と「取り消し」機能
- 多重タップ防止ブロック
- 相対日付（○日後・○週間後）の手入力UI
- 毎週○曜日の繰り返しタスク機能
- 全データ消去機能（設定画面）

## GAS同期

### TaskFlow側の設定

設定画面の「Google Apps Script 同期」に、GAS WebアプリURLとAPIキーの両方を入力して保存します。URLは `https://script.google.com/macros/s/DEPLOYMENT_ID/exec` 形式です。APIキーはGAS側の `TASKFLOW_API_KEY` スクリプトプロパティと同じ値にします。TaskFlowではURLとAPIキーを別々に保存し、どちらかが未設定なら送信しません。POST本文は `{apiKey, tasks}` で、URLやアプリのログにはキーを含めません。

### GASの設定・デプロイ

1. Google Sheetsで同期先のスプレッドシートを作成し、「拡張機能」→「Apps Script」を開きます。リポジトリの [`gas/Code.gs`](gas/Code.gs) の内容をApps Scriptのエディタへ貼り付けて保存します。スプレッドシートに紐づくスクリプトとして使ってください。
2. Apps Scriptの「プロジェクトの設定」→「タイムゾーン」を `Asia/Tokyo` にします。従来の期限日時（`deadline`）は日本時間として解釈されます。
3. 「プロジェクトの設定」→「スクリプト プロパティ」に `TASKFLOW_API_KEY` を追加し、十分に長いランダムな専用キーを設定します。キーをソースコードへ書かず、TaskFlow設定画面にも同じ値を入力します。
4. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」を選択します。「次のユーザーとして実行」は自分、「アクセスできるユーザー」は組織ポリシーで許可される範囲に設定します。TaskFlowは匿名リクエストでAPIキー認証するため、匿名アクセスが許可されないと同期できません（Googleアカウントの認証情報を送る方式ではありません）。デプロイ後の `/exec` URLをTaskFlowの設定画面に登録します。
5. Apps Scriptエディタで `installTaskNotificationTrigger` を選び、一度「実行」します。Googleの権限確認が表示されたら、スプレッドシートの読み書き、メール送信、トリガー実行を許可します。この関数は既存の同じ通知スキャン用トリガーを置き換え、5分ごとのトリガーを1つ作成します。アカウントを切り替える場合は、旧アカウントのトリガーを削除して新しいアカウントで作成してください。
6. TaskFlowの「Google Apps Script 同期」でWebアプリURLとAPIキーを保存します。同期成功後、スプレッドシートに `tasks` シートが作成され、最新スナップショットに置き換わります。

メールの宛先は、インストール型トリガーを作成したアカウントです。トリガーは作成者の権限で実行されます。Apps Scriptへ貼り付けた後の初回実行で権限を許可し、そのアカウントのGmailで受信できることを確認してください。`_notification_log` シートには重複送信を避ける永続記録が保存されます。同期処理は `tasks` シートだけを置き換え、このログシートには触れません。どちらのシートも手動で編集・削除しないでください。

匿名公開のWebアプリではAPIキーが漏れると第三者に呼び出される可能性があります。専用キーを使い、他の重要な認証情報を流用しないでください。キー未設定または不一致の場合、受信したタスク内容は処理しません。APIキー認証は完全な認証・保護ではありません。組織ポリシーに従い、公開アクセスが許されない場合はこの同期方式をデプロイしないでください。

### 期限メール通知

```json
{
  "apiKey": "(スクリプトプロパティと一致するキー)",
  "tasks": [
    {
      "id": "TASK_ID",
      "title": "TASK_TITLE",
      "startDate": "",
      "deadline": "2026-11-21T09:00",
      "deadlineAt": "2026-11-21T00:00:00.000Z",
      "priority": "2",
      "recurring": "none",
      "memo": "",
      "completed": false,
      "notificationMode": "within24h",
      "notificationAt": "",
      "extraDates": [],
      "urls": [],
      "images": [],
      "subtasks": [],
      "createdAt": "ISO_8601_TIMESTAMP"
    }
  ]
}
```

`tasks` は変更分ではなくIndexedDB内の全タスク配列です。タスク追加・更新・削除、復元、全消去後に最新状態が送信され、起動時とオンライン復帰時にも全件を送信します。`deadlineAt` は期限の絶対時刻（UTC ISO 8601）、`notificationMode` は `none` / `within24h` / `deadlineMorning` / `custom`、`notificationAt` はカスタム通知の絶対時刻（UTC ISO 8601）です。古いタスクに通知方式がない場合は `none` として扱い、過去タスクから予期しない通知が発生しないようにしています。新規タスクも初期値は「通知しない」です。繰り返しタスクはA/B方式を引き継ぎ、カスタム通知は次回タスクへ引き継ぎません。

通知方式はタスクごとに選べます。

- **A: 期限の24時間前以内**: 期限の24時間前から期限までの間に、最初のスキャンで通知します。期限を過ぎたタスクは通知しません。
- **B: 期限当日の朝**: 日本時間で期限当日の07:00以降、期限時刻までに通知します。5分間隔でスキャンするため、07:00ちょうどの送信は保証されません。
- **カスタム: 指定日時**: 年月日時分を入力します。入力した端末のローカル時刻を絶対時刻へ変換します。GASの実行遅延により指定時刻から数分以上遅れることがあります。指定分ちょうどの送信は保証されません。

5分間隔の時間主導トリガーが、`tasks` シートの最新全件スナップショットを読み、未完了タスクだけを判定します。同時刻に該当するタスクは1通のダイジェストメールにまとめます。送信済みタスクと通知条件の組み合わせは `_notification_log` に記録され、同じ条件では再送しません。タスクの期限や通知日時を変更すると新しい通知条件として扱います。

Google Apps Scriptの実行は指定時刻から遅れることがあり、分単位のカスタム通知を保証するものではありません。5分トリガーは1日約288回実行されます。個人アカウントではトリガー実行の合計が1日90分（288回に均等配分すると平均約18.75秒/回）、メール宛先が1日100件、トリガー数がユーザー・スクリプトあたり20個などのクォータがあります（Workspaceアカウントは別枠）。実際の上限は変更される可能性があります。メールは該当タスク群ごとに1通ですが、頻繁な別時刻の通知はメールクォータを消費します。Apps Scriptの「実行数」で動作状況や失敗を確認してください。

TaskFlowは `POST`、`Content-Type: text/plain;charset=UTF-8`、`mode: no-cors` で本文を送ります。CORS応答を読み取れないため、送信要求が完了してもGASの成功は確認できません。受信・エラーはApps Scriptの実行数とスプレッドシートで確認してください。通信失敗時もIndexedDBへの保存は継続し、失敗分の永続キューはなく、オンライン復帰時または次の変更時に再送します。Google Sheetsのセル上限を超える大きなタスク項目は同期できず、その場合は直前の `tasks` スナップショットが保持されます。
